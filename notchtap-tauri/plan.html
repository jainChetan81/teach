NotchTap frontend and Tauri active

Learn the desktop stack through the app you already use. Start with React, state, CSS, and motion. Cross into Tauri and Rust only when a real UI issue needs it.

Why this track exists

NotchTap has UI problems you have noticed for weeks. Fixing those problems is the course. Each sitting pairs one frontend idea with one visible part of the app. Tauri and Rust arrive later, at the exact boundary where the frontend stops owning the answer.

The working rule

ConceptNotchTap question
React stateWhich value decides the surface that appears?
Custom hooksHow does a Rust event become a React value?
CSS and MotionWhy does the card jump, clip, or animate incorrectly?
Component testsHow do we keep a fixed visual rule from returning?
Tauri eventsHow does Rust push state into the overlay?
Tauri commandsHow does the settings window ask Rust to act?

Objectives

  • Trace one pixel from Rust-owned state to a React component and its CSS rule.
  • Explain the overlay and settings frontends without reading every file.
  • Reproduce each chosen UI issue before changing code.
  • Fix at least three user-visible issues with regression tests.
  • Explain when a fix belongs in React, CSS, Tauri IPC, or Rust.

Start here

Read lesson 0001 — the seven wires. It covers where the data comes from, where it sits, and the three things that start an animation. 20 minutes, no app code changes. Keep the wire table open beside it.

What changed in the repo — 2026-08-15

The app repo moved under you today. Six things to know before trusting your mental model. Each one names the files to go read.

  • The seventh wire vanished, then came back. src/useSlotState.ts — the listener for slot-state, emitted from src-tauri/src/engine.rs via emit_slot_state — was accidentally deleted while ~15 files still imported it. One missing file, a cascade of TypeScript errors across the import graph, build dead. It has been restored unchanged with git restore, so the wire table is correct again. Good case study: when the compiler screams from fifteen places at once, suspect one missing module, not fifteen bugs.
  • New app-only token file. src/notchtap-tokens.css holds tokens that belong to NotchTap alone (currently just --media-mint, which moved out of vendor/shared-ui/design/tokens.css). It loads right after the shared tokens in both entries: src/main.tsx for the overlay, src/settings/base.css for settings. src/entryImportOrder.test.ts now fails CI if that order drifts.
  • OpenCode adapter export changed. adapters/opencode/notchtap.ts now exports server plus a default { id: "notchtap", server }, the shape OpenCode 1.18 expects.
  • Root CLAUDE.md was condensed. Same facts, telegraphic style. If a sentence there reads clipped, that is deliberate.
  • New docs/FIGMA_DESIGN_SYSTEM.md. Two Figma files mirror the code tokens. Code is the authority; Figma is downstream.
  • New unified.html at the repo root. A large unified control/prototype/research reference. Not wired into the build.
