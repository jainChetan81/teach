NotchTap wire table

Every piece of data that enters the overlay, and the one file that receives it. Verified against the repo on 2026-08-03.

The rule this table encodes

The overlay window fetches nothing, polls nothing, and stores nothing on disk. Rust decides, Rust emits, React renders. There are exactly seven named event channels. If a value on screen is wrong, it came through one of these seven rows.

The boot seeds

A React app can mount before or after Rust's first emit. NotchTap covers both by also planting globals into the page at load time (lib.rs, on_page_load), then emitting anyway. Whichever arrives second wins, and both paths run the same validator.

When a wire fires

On change, never on a clock. Three examples of that discipline in the Rust source:

  • emit_slot_state runs only where the displayed slot actually changed (event.rs:457 doc).
  • status_state_if_changed returns nothing when the status is identical.
  • emit_tab_selection_if_transitioned returns early when the selection matches the last one (status.rs:315).

Consequence for debugging: a screen that never updates is usually a wire that never fired, not a React component that failed to re-render.
