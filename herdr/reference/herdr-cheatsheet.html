What survives what (lesson 0002)

DisasterWhat you get back
Client closes / SSH dropsEverything. The server never stopped.
Detach ctrl+b qEverything. Same mechanism, done politely.
Server restart / rebootShape only — workspaces, tabs, panes, cwd, layout, focus (from session.json). Fresh shells.
…+ screen history replayShape + recent pane text (session-history.json). Off by default: scrollback leaks secrets.
…+ agent integrationShape + the conversation. Herdr stores the agent's own session id and asks it to resume.
herdr update --handoffRunning panes move to the replacement server. Experimental.

One sentence: herdr keeps processes alive by never stopping them; everything else is reconstruction from notes.

Inspect & debug

Do thisHow
Is a server / client alive?herdr status
Live session state from the serverherdr api snapshot
The full protocol contractherdr api schema --json
What's on disk~/.config/herdr/session.json (shape), herdr-server.log, herdr.sock
Apply config, keep panes aliveherdr server reload-config — returns status: applied. Use this, not stop.
Stop the server — kills every pane and agentherdr server stop — last resort. There is no herdr server restart. The server does not restart itself; a client command reports stopped and starts nothing
Read a pane's outputherdr pane read <id> --source recent --lines 400 — --source visible returns only the current screen and will make a restored pane look empty
Named, fully separate sessionherdr --session <name> · socket at ~/.config/herdr/sessions/<name>/herdr.sock

Socket API (agents driving herdr)

Newline-delimited JSON over ~/.config/herdr/herdr.sock. Send {"id":"req_1","method":"ping","params":{}}, get {"id":"req_1","result":{"type":"pong"}}. The CLI below is just a wrapper over it.

herdr workspace create --cwd ~/project --label api
herdr tab create --label logs
herdr pane split w1:p1 --direction right
herdr pane run w1:p2 "just test"
herdr agent wait w1:p1 --until done
herdr pane read w1:p2 --source recent-unwrapped

Mental model (one line)

The server holds the PTYs; every terminal — Mac, phone, VPS — is a disposable view onto them. Mosh keeps the connection alive; herdr keeps the work alive.
