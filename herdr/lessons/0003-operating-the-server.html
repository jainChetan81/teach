Operating the server

Lesson 0003 · ~30 min · completes hdr-5 · feeds capstone ps-5, ps-6

Why this lesson

Lessons 0001 and 0002 were about what herdr is. This one is about not breaking it. Every fact below was measured on your own Mac mini on 28 Jul 2026, and four of them contradict what a reasonable person would assume. One of them silently kills every running agent. Another one is the single most likely thing to break your capstone, and it bit you on both machines in one evening.

The capstone asks you to move a live session between devices. You cannot do that if you don't know which commands are safe, whether the server comes back on its own, and whose config wins when two machines disagree.

Phase 1 — The three server verbs, and the one that doesn't exist

Run this first and read the output before anything else:

VerbWhat it does to your live panesWhen
server stopKills every one of them. Agents included.Almost never. Last resort.
server reload-configNothing. They keep running. Applies config.toml in place.Every config change.
server live-handoffMoves live panes to a new local server.Upgrades, without losing work.
The trap: you change config.toml, you want it applied, you reach for "restart", it doesn't exist — so you reach for server stop instead. That is the wrong instinct and it costs you every running agent. Measured on the mini: reload-config returned {"diagnostics":[],"status":"applied"} and all three panes were still alive afterwards. Use it.

Phase 2 — The server does not come back by itself

This is the assumption worth destroying. It feels like a background service that respawns on demand. It does not.

A client command reports the truth and walks away. If nothing starts the server, nothing starts the server. On the mini this is now handled by a LaunchAgent with two settings worth understanding:

  • RunAtLoad = true — starts it when you log in.
  • KeepAlive → SuccessfulExit = false — restarts it if it crashes, but leaves it down after a deliberate server stop. Without that second part you could never stop it to test anything.
Why this matters for the capstone: a LaunchAgent is a user agent. It waits for a login. If the host reboots and nobody logs in, there is no server, no socket, and nothing to attach to from your other device. On the mini, FileVault makes that worse — the machine sits at the disk-password screen and not even Tailscale starts. Remote access holds while the host stays powered and logged in, and not one second past a reboot.

Phase 3 — Reading a pane without fooling yourself

herdr pane read takes a --source flag, and the default is not what you want when you're checking whether something was restored.

visible returns only the current viewport — one screen. recent returns the buffer. On the mini this exact confusion made a working feature look broken: visible reported 0, 18 and 19 lines across three panes, while recent found 127 and 378. Nothing was wrong. The question was wrong.

Correction to lesson 0002: pane_history does not save one screenful, and its restore half is no longer unproven. Measured across two clean shutdowns: panes saved 110 and 308 lines against a 40-row viewport, and after a full stop/start cycle 59/90 and 201/286 of those lines came back verbatim. It saves up to the available scrollback. One caveat: a pane running an agent restores the agent, not the screen — resume_agents_on_restore relaunches it and the agent clears its own display on start.

Phase 4 — The PATH trap that kills herdr --remote

This is the one that matters most, because it breaks the exact thing the capstone is built on, and the error message tells you nothing useful.

Homebrew installs a line into ~/.zprofile. .zprofile only runs for login shells. When you run ssh host 'some-command', zsh starts non-interactive and non-login — so it reads ~/.zshenv and nothing else. /opt/homebrew/bin never lands on PATH, and herdr and mosh-server simply do not exist as far as that shell is concerned.

Why env -i and not just zsh -c: because you are almost certainly already inside a shell that has the fixed PATH. Your test inherits it and passes while the underlying config is still broken. This wasted real time on the mini — the "proof" commands passed before anything was fixed. env -i throws the environment away and asks the question properly.

The fix is to move the Homebrew line to ~/.zshenv, which every zsh reads, with a guard so nested shells don't stack PATH entries:

if [ -z "${HOMEBREW_PREFIX:-}" ] && [ -x /opt/homebrew/bin/brew ]; then
  eval "$(/opt/homebrew/bin/brew shellenv)"
fi

Check your work with zsh -lc 'echo $PATH' | tr : '\n' | sort | uniq -d. It should print nothing.

Phase 5 — Whose config wins when you attach from another device

herdr renders the UI server-side. Sit at your MacBook, run herdr --remote mini, and the pixels are decided by the mini's config.toml. This surprises people constantly.

SettingWhich machine decides
Theme, sidebar rows, toasts, sound, accentHost (the one running the server)
experimental.kitty_graphicsClient — it needs your local terminal's support
[keys] bindingsClient only. They do not reach a remote session
PluginsClient. A binding for a plugin the host lacks just no-ops
A real consequence: the mini used to set theme.auto_switch = true with a light theme name. Attaching from the MacBook let the mini flip the MacBook's display to light, and the MacBook's own dark-forcing could not stop it — because the MacBook was never the one deciding. Fixed by pinning auto_switch = false on the host. Never fix this by copying one config over the other; they are different roles.

Check yourself (instant feedback)

1. You edited config.toml and want it live. Two agents are mid-task. What do you run?

2. The server is stopped. You run herdr session list. What happens?

3. ssh mini 'herdr --version' says command not found, but it works when you SSH in and type it. Why?

4. You attach from your MacBook to the mini. Which machine's theme do you see?

Done with this lesson when

You can name the three real server verbs and say which one is safe with agents running; you can explain why env -i is the only honest PATH test; and you can answer, without looking: "I attached from my laptop and the theme is wrong — which machine do I fix?" Then tick hdr-5 on the herdr plan.
